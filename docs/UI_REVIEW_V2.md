# OptiForge 前端体验 · 第二轮审核

日期：2026-10-27。依据用户对首轮布局的反馈：信息密度过大；主界面优先 2D 光路与表面属性；像质分析进入次级页面；采用更接近 Gemini iPhone / Siri 的柔和动效体验；先审核前端，后接入功能。

## 本轮实现

- 主界面：大幅 2D 光路、表面选择、当前表面的曲率半径/面后厚度/材料。全部表面属性以详情弹窗展开。
- 二级分析页：点列图、MTF、波前切换，视场选择，MTF T/S 图例开关。主页不再常驻分析图、处方表、任务列表或项目树。
- 双主题：浅色、深色、跟随系统，图形与所有浮层使用相同的主题令牌。
- 配色最终按光学设计用途调整为中性白与石墨灰，镜片和选中状态使用灰阶。用户否定过于温馨的暖灰铜棕方案后已完整替换；不使用蓝紫渐变或彩色光球。同步使用单色进度环与有限时长的柔和光影。
- 彩色专门用于光学数据：光路和 MTF 的轴上/0.7/边缘视场使用固定绿/红/青映射。光路同时使用实线/虚线/点线；图例支持单独显隐。点列图按视场分栏、按 486/588/656 nm 波长着色，避免混淆视场与波长。
- 清理首页徽标、眉题、重复单位、只读提示和零散演示备注；演示边界集中在“关于”。所有可见文字至少 14px，保留必要的属性名称、数值与单位。
- 动效：弹性悬停/按压、导航选中块、表面选中块、属性数值滑入/滑出、页面切换、详情弹窗、同步状态的有限时长光晕。
- 保留外部 Agent 对话方式。本轮没有增加聊天框、语音采集或 LLM API 接入。

前端源码在 `frontend/`，首轮预览继续保留。新预览由同一 React 构建生成，避免独立维护两套展示逻辑。

## 开源项目的实际使用方式

1. **Motion 14.6.0 / MIT**：已安装为运行依赖。使用 `motion`、`AnimatePresence`、布局选中块、手势反馈与 `MotionConfig`。来源：https://github.com/motiondivision/motion ，文档：https://motion.dev/docs/react-animation 。不使用 Motion+。
2. **Lucide React 1.62.0 / ISC**：已安装为运行依赖，统一图标。部分继承 Feather 的图标另保留其 MIT 声明。来源：https://github.com/lucide-icons/lucide 。
3. **React 19.3.1 / MIT、Vite 8.3.5 / MIT**：前端结构与构建，版本锁定在 `package-lock.json`。
4. **Magic UI Border Beam**：查看官方示例，参考“状态变化时边缘亮起”的交互概念；当前光晕为自主实现，未复制其组件或引入依赖。来源：https://magicui.design/docs/components/border-beam 。
5. **React Bits**：本轮核对当前仓库许可为 MIT + Commons Clause，不能称为无附加条件的 MIT；仅作为视觉研究候选，未复制代码或引入依赖。许可来源：https://github.com/DavidHDev/react-bits/blob/main/LICENSE.md 。

9 个运行依赖的原始许可保存在 `frontend/THIRD_PARTY_NOTICES.md`，聊天预览也保留声明。无需安装额外 skill 才能完成当前前端工作。

## 审核与数据边界

- 所有光路、处方和分析均为 UI 样例，未进行光学建模、追迹或优化。
- 同步按钮仅演示状态和数值切换，未连接真实 Agent。示例半径在 `−39.605` 与 `−39.800` 间切换。
- 本轮审核视觉、密度、动效手感与页面层级。只有用户认可后，才进入真实工程状态的功能接入。
- 原稳定工作区保持原提交。所有改动与提交仅在本地，未 push 或部署。
