# 第二批同步：方案问题与决定

本文件记录实施中影响身份与发布契约的问题；原计划仍由规划聊天在 `D:\mcp gemini zemax\plan.md` 维护。

## D1：元数据读取失败后，缓存身份不能授权下一次写入

问题：模型 a 成功切换到 b 后，若项目元数据读取失败，兜底状态保留 a 的项目字段。仅更新 state_version 而继续接受该缓存上下文，仍可能把面向 a 的修改执行在 b 上。

备选方案：一是所有显示失败都阻止后续写入；二是单独记录上下文可信度，仅在工程身份不可确认时阻止针对当前模型的操作；三是自动重试上一写入。第一种会把纯快照显示失败扩大为写入失败，第三种可能重复写入。

规划聊天已决定采用第二种：发布 `context_valid`。元数据读取失败时为 false，保留字段仅供诊断；拒绝修改、计算、保存和上下文写入，返回 `WORKBENCH_STATE_UNCERTAIN`。显式读取与 New/Load/Template 恢复路径仍可使用，原提案门禁不变。成功重新观察并发布真实元数据后恢复可信度，版本增加使旧上下文失效。

实施状态：已实现并增加独立回归，待本批整体复审。纯视图快照失败保持成功的业务结果，且不因此把已确认的项目身份标为不可信。

## 已按既定计划处理的风险

- 共聚焦离焦扫描与配置上下文失败时无法证明临时修改恢复：保守标 uncertain，普通快照刷新不能解除；成功重新载入或新建会话后才能恢复。后续操作只回滚到其执行前状态，不能消除更早的 uncertainty。操作结果造成的不确定性在读取元数据前独立持久记录，身份读取恢复不等于模型恢复。新增两条独立回归覆盖这两个复审路径，未重写原光学算法。
- 三个 CAD 导出工具可能在导出前切换活动项目：登记为受上下文保护的 context 类，包含失败后元数据变化的观察测试。
- 中文项目名不能直接放入浏览器 ByteString 请求头：`X-Expected-Context` 使用 URI 编码的 JSON，服务端对应解码；MCP JSON 请求体仍按标准 JSON 编码。

以上属于第二批身份保护和错误语义的实现，不包含光线、分析面板或独立内核。
